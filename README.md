<h1 align="center">IVTrace</h1>

<p align="center">
  Автоматизированное снятие амплитудной характеристики датчиков тока и
  напряжения — GUI и CLI в одном приложении.
</p>

<p align="center">
  <a href="https://github.com/alexlegoshin/IDM-IVTrace/releases/latest">Последний релиз</a>

  <a href="https://github.com/alexlegoshin/IDM-IVTrace/releases">Все релизы</a>
</p>

---

Источник (тока или напряжения) задаёт возбуждение на первичной обмотке
датчика, плата реле переключает полярность, мультиметр измеряет выходной
сигнал. Результат — CSV с точками измерения и PNG с графиком амплитудной
характеристики и приведённой погрешности.

## Возможности

- GUI (Tkinter) и CLI из одного исполняемого файла.
- Автообнаружение приборов по `*IDN?`, ручной ввод адреса как запасной путь.
- Обе полярности через плату реле за один проход, пресеты схемы прохода
  (сходящийся/расходящийся через ноль, полный гистерезис).
- Число витков, смещение нуля, усреднение, отсечка по погрешности.
- Приведённая погрешность по ГОСТ 8.401-80 — и в отчёте, и в живой отсечке
  во время измерения (при заданных номинале и коэффициенте преобразования).
- Плавное нарастание тока, адаптивное охлаждение и плавный проход нуля в
  петле гистерезиса (BETA).
- Настраиваемое число контрольных перепромеров при подозрении на брак.
- Свой сценарий развёртки — текстовый DSL вместо начала/конца/шага (BETA).
- Учёт межповерочных интервалов приборов, экспорт результатов в XLSX.
- Предполётные самотесты — гейт перед каждым измерением.
- Инсталлятор с автообновлением по GitHub Releases (Windows).
- Подробный файловый журнал (в папке кэша) — для диагностики без гадания.

## Быстрый старт

### Windows — готовая сборка

1. **Установите NI-VISA.** Без неё программа не увидит ни один прибор.
   [Скачать с сайта NI](https://www.ni.com/en/support/downloads/drivers/download.ni-visa.html) —
   ставится с настройками по умолчанию, прав администратора на дальнейшую
   работу не требует.

2. **Установите драйверы приборов, которым они нужны** (не всем):

   - **Плата реле** (чип CP2102) — без драйвера Windows покажет в диспетчере
     устройств «Код 28», виртуальный COM-порт не появится:
     [CP210x USB to UART Bridge VCP Driver, Silicon Labs](https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers?tab=downloads).
   - **Источник напряжения GW Instek GPP-4323/GPP-74323** (если он у вас
     есть) — определяется Windows как vendor-specific USB-устройство, а не
     обычный COM-порт, и тоже не заработает без официального драйвера:
     [GW Instek USB Driver Ver.1.0.0.3](https://www.gwinstek.com/en-global/download/downloadFile/14674)
     (`driverSetup.exe`, ставить **от администратора**).
   - Мультиметры (AKIP, RIGOL) и источник тока — обычные USB-TMC устройства,
     отдельного драйвера не требуют, NI-VISA видит их «из коробки».

3. Скачайте `IVTrace-<версия>-win64.zip` со страницы
   [Releases](https://github.com/alexlegoshin/IDM-IVTrace/releases/latest) и
   распакуйте **целиком** в отдельную папку.

4. Запустите `Setup.exe` — установит программу, создаст ярлыки и будет
   предлагать обновления при следующих запусках. Либо запустите
   `IVTrace\IVTrace.exe` напрямую — без установки, portable-режим.

   При первом запуске Windows SmartScreen может показать «Windows защитила
   ваш компьютер» (exe не подписан цифровой подписью) — «Подробнее» →
   «Выполнить в любом случае».

### Из исходников — Windows / macOS / Linux

```bash
conda create -n IVTrace python=3.11 -y
conda activate IVTrace
pip install -r requirements.txt

python run.py                 # GUI (где есть дисплей)
python run.py measure ...     # измерение из консоли
python run.py analyze ...     # построение графика по CSV
python run.py selftest        # диагностика окружения
```

На macOS/Linux готовой GUI-сборки нет — только запуск из исходников
(Tkinter входит в стандартный Python). Для реальной работы с приборами
всё равно нужна NI-VISA — NI выпускает её и под Linux/macOS. Драйверы из
шага 2 выше проверялись только на Windows — на macOS/Linux ищите
инструкции у производителей отдельно (CP210x на Linux обычно уже есть в
ядре, к GW Instek под не-Windows отдельно не обращались).

## Приборы

| Тип | Модели | Драйвер |
|---|---|---|
| Мультиметр (ток/напряжение) | AKIP-2101 / Siglent SDM3055, АКИП-B7-78/1, RIGOL DM3068 | не требуется (USB-TMC) |
| Источник тока | ITECH IT-M (АКИП-1162) | не требуется (USB-TMC) |
| Источник напряжения | GW Instek GPP-74323 (Tracking Series) | нужен, см. «Быстрый старт» |
| Плата реле | Serial (чип CP2102), автообнаружение COM-порта | нужен, см. «Быстрый старт» |

Новый прибор добавляется JSON-конфигом в `instruments/` — без кода, если
протокол укладывается в существующую схему.

## Разработка и тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

Тесты работают на заглушках, реального железа не требуют. Тот же набор —
предполётный гейт перед каждым измерением.

## Известные ограничения

- Выход датчика по напряжению — BETA, не проверено на реальном стенде.
- Источник напряжения GPP-74323 — команды по документации производителя.
- Самотесты виртуальные: ловят поломки кода, не заменяют проверку железа.
