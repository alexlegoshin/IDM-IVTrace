# IVTrace v1.3ae

Приложение для автоматизированного снятия амплитудной характеристики
датчиков тока и датчиков напряжения с токовым выходом. Работает **и как
графическое приложение (GUI), и как консольная утилита (CLI)** — из одного
исполняемого файла.

Источник (тока или напряжения) задаёт возбуждение на первичной обмотке
датчика, плата реле автоматически переключает полярность, мультиметр
измеряет выходной ток датчика. Результат — CSV с точками измерения и PNG
с графиком амплитудной характеристики и приведённой погрешности.

## Быстрый старт (рабочий ПК)

Программа поставляется как **portable-папка** `IVTrace\` с файлом
`IVTrace.exe` внутри. Python устанавливать **не нужно** — он уже внутри.

1. **Установите NI-VISA** (см. следующий раздел). Это единственная
   обязательная установка, требующая прав администратора.
2. Скопируйте папку `IVTrace` целиком в любое место (например на рабочий
   стол или на сетевой/локальный диск).
3. Подключите приборы (мультиметр, источник, плату реле) по USB.
4. Запустите `IVTrace.exe` — откроется графический интерфейс.
5. В шапке окна убедитесь, что горит зелёный статус **«NI-VISA: OK»**. Если
   красный **«NI-VISA не найдена»** — вернитесь к шагу 1.

Проверить готовность окружения без запуска измерения можно командой:

```bat
IVTrace.exe selftest
```

Она выведет статус NI-VISA и прогонит виртуальные самотесты.

## Требование NI-VISA — обязательно

Приборы (мультиметр и источник) подключаются по **USB-TMC** и работают через
**NI-VISA** — системную реализацию стандарта VISA от National Instruments.
Библиотека `pyvisa`, встроенная в программу, — лишь обёртка; ей нужен
установленный на ПК бэкенд NI-VISA. **Без NI-VISA приложение измерять не
будет** и честно об этом сообщит.

> **Почему нельзя обойтись без установки.** Для USB-TMC не существует
> по-настоящему «portable» пути без драйвера: чисто-питоновские бэкенды
> требуют перепривязки USB-устройства к WinUSB (Zadig) — это тоже права
> администратора, и это ломает работу приборов в другом ПО. Поэтому выбран
> честный путь: один раз ставится NI-VISA, дальше всё работает.

### Установка NI-VISA

1. Дистрибутив NI-VISA поставляется **вместе с программой** (или скачивается
   с сайта NI: «NI-VISA» → выбрать версию Runtime/Full).
2. Запустите установщик **от администратора**, следуйте мастеру, по
   завершении перезагрузите ПК.
3. Подключите приборы. Откройте **NI MAX** (ставится вместе с NI-VISA) —
   приборы должны быть видны в разделе *Devices and Interfaces* как
   USB-ресурсы (`USB0::0x....::INSTR`).
4. Запустите `IVTrace.exe selftest` — строка **VISA** должна быть «OK».

### Как программа проверяет NI-VISA

- **GUI**: индикатор в правом верхнем углу («NI-VISA: OK …» / «NI-VISA не
  найдена»). Кнопка «Старт измерения» разблокируется только при OK.
- **CLI**: перед каждым `measure` выполняется проверка; при отсутствии
  NI-VISA измерение отменяется с инструкцией.
- **Диагностика**: `IVTrace.exe selftest`.

## Предполётные самотесты

Перед реальной работой с железом (команда `measure` и старт измерения в GUI)
программа прогоняет **виртуальный тест-набор** собственного кода (около 90
быстрых тестов на заглушках, ~10–15 секунд). Если код повреждён или
рассогласован — тесты падают, и **измерение не запускается**.

Это дешёвая страховка оборудования: не панацея (тесты виртуальные, живого
железа не касаются), но защищает от очевидных поломок логики, способных
подать неверную команду на источник или мультиметр.

- В **GUI** самотесты идут в фоне при запуске; «Старт» доступен только после
  их успеха. Есть галочка «Игнорировать самотесты» (по умолчанию выключена).
- В **CLI** используйте глобальный флаг `--skip-selftest` (не рекомендуется):

  ```bat
  IVTrace.exe --skip-selftest measure ...
  ```

- Прогнать отдельно: `IVTrace.exe selftest`.

## Графический интерфейс (GUI)

Запуск: двойной клик по `IVTrace.exe`, либо `IVTrace.exe gui`.

- **Тип возбуждения** — ток или напряжение (переключает единицы А/В и
  доступность поля «Ограничение напряжения»).
- **Параметры измерения** — начало, конец, шаг, задержки, комментарий.
  Значения подставляются из прошлого запуска.
- **Приборы (необязательно)** — если оставить пустыми, адреса мультиметра,
  источника и порт реле определяются автоматически. Можно задать вручную
  (VISA-адрес / `COMx`).
- **Старт / Стоп** — «Старт» запускает обе полярности через реле; «Стоп»
  корректно прерывает проход между точками (источник и реле выключаются).
- **Журнал** — весь ход измерения в реальном времени.
- **График** — задайте `I ном.` и коэффициент `1:X`, нажмите «Построить
  график»: строится амплитудная характеристика и приведённая погрешность,
  PNG сохраняется рядом с CSV.

Данные пишутся в папку `data\` рядом с `IVTrace.exe`.

## Командная строка (CLI)

```
IVTrace.exe [--data-dir DIR] [--skip-selftest] <команда> [опции]
```

Глобальные флаги (`--data-dir`, `--skip-selftest`) ставятся **до** команды.

### measure — измерение (обе полярности через реле)

Датчик тока (возбуждение источником тока):

```bat
IVTrace.exe measure --excitation current --start 0 --stop 100 --step 5 ^
    --vlimit 3 --delay 1 --cool 1.5 --label "VAC 4646X100"
```

Датчик напряжения (возбуждение источником напряжения):

```bat
IVTrace.exe measure --excitation voltage --start 0 --stop 64 --step 4 ^
    --delay 1 --cool 0.5 --label "VoltageSensor1"
```

Без флагов параметры запрашиваются интерактивно (с подстановкой значений из
предыдущего запуска). Ручные адреса: `--dmm-addr`, `--src-addr`,
`--relay-port`.

### analyze — построение графика и расчёт погрешности

```bat
IVTrace.exe analyze --inom 150 --ratio 1500
```

`--inom` — номинальный первичный ток датчика (А); `--ratio` — коэффициент
преобразования 1:X (передаётся X). По умолчанию берётся самый свежий CSV в
`data\`; конкретный файл — через `--file путь.csv`. `--no-show` — не
открывать окно, только сохранить PNG.

### selftest — диагностика

```bat
IVTrace.exe selftest
```

Проверка NI-VISA + прогон самотестов. Код возврата 0 — всё в порядке.

### gui — графический интерфейс

```bat
IVTrace.exe gui
```

## Портативность и доменные ПК

| Компонент | Нужно ставить? | Права админа |
|---|---|---|
| Python | **Нет** — внутри exe | — |
| Библиотеки (pyvisa, pandas, matplotlib…) | **Нет** — внутри exe | — |
| **NI-VISA** | **Да, один раз** | **Да** (только на установку) |
| Драйверы USB-serial платы реле | Обычно уже в Windows | Как правило нет |

То есть на доменном ПК администратору нужно **один раз** установить NI-VISA
(и, при необходимости, USB-serial драйвер для платы реле — CH340/CP210x/FTDI,
если Windows не поставила его автоматически). Само приложение
устанавливать не требуется — папка `IVTrace` копируется и запускается как
есть.

## Запуск из исходников (Windows / Linux / macOS)

На Linux/macOS графической сборки не предусмотрено — используйте CLI из
исходников (Python ставится штатно через пакетный менеджер / conda).

```bash
# 1. Создать окружение (пример через conda)
conda create -n IVTrace python=3.11 -y
conda activate IVTrace

# 2. Зависимости
pip install -r requirements.txt

# 3. Запуск
python run.py                 # GUI (где есть дисплей)
python run.py measure ...     # измерение
python run.py analyze ...     # анализ
python run.py selftest        # диагностика
```

> На Linux/macOS NI-VISA также требуется для реальной работы с приборами
> (NI выпускает NI-VISA под Linux и macOS). Без приборов доступны `analyze`
> и `selftest`.

## Сборка portable-exe

Собирается на Windows в окружении с зависимостями разработки.

```powershell
conda activate IVTrace
pip install -r requirements-dev.txt
.\build_windows.ps1
```

Результат — `dist\IVTrace\IVTrace.exe` (+ папка `_internal`). Копируется
целиком как portable-папка. Скрипт перед сборкой прогоняет самотесты и
добавляет в PATH DLL-папки conda-окружения (иначе PyInstaller не находит
`libffi`/`_ctypes`, `tcl/tk` и exe падает с «DLL load failed»).

Сборка описана в `ivtrace.spec` (onedir, один консольный exe для GUI и CLI;
в сборку упаковываются `instruments\` и `tests\`; `pyvisa-py` намеренно
исключён, чтобы не маскировать отсутствие NI-VISA).

## Приборы

### Мультиметры (`instruments/multimeters/`)

| Файл | Модель | Диапазоны, А |
|---|---|---|
| `akip2101.json` | AKIP-2101 / Siglent SDM3055 | 0.0002 … 10.0 |
| `akipb778.json` | АКИП-B7-78/1 (Picotest) | 0.01 … 3.0 |

Всегда работают в режиме постоянного тока (`SENS:CURR:DC`). Измерение идёт
командой `READ?` при **выключенном** авто-диапазоне прибора
(`SENS:CURR:DC:RANG:AUTO OFF`) — диапазон переключает сама программа. Это
важно: команда `MEAS?`/`CONF?` каждый раз сбрасывала бы диапазон в AUTO и
делала ручное управление бессмысленным.

### Источники тока (`instruments/current_sources/`)

| Файл | Модель |
|---|---|
| `akip1162.json` | ITECH IT-M series |

### Источники напряжения (`instruments/voltage_sources/`)

| Файл | Модель |
|---|---|
| `gpp74323.json` | GW Instek GPP-74323 |

Источник напряжения объединяет каналы **CH1 (master) + CH2 (slave) в режиме
Tracking Series** (`TRACK1`) — объединённый диапазон 0…64 В на клеммах
CH1(+) и CH2(−). Полярность на первичке меняет плата реле, поэтому источник
всегда однополярный.

> **Нюанс GW Instek:** `*IDN?` этой серии не содержит первую цифру номера
> модели — GPP-74323 отвечает как `GPP-4323` (это учтено в `keywords`).
> Команды выверены по официальному руководству, но на живом железе кодом ещё
> не проверялись — при первом запуске проследите за логом инициализации.

### Плата реле

Serial, 115200 бод, `\r\n`. После открытия порта ~5 c на загрузку
контроллера. Команды (ответ — `OK`): `BEN` (связь), `IFW` (прямое), `IRW`
(обратное), `I_0` (выключить). Порт определяется автоматически или задаётся
вручную (`--relay-port` / поле в GUI).

### Добавление нового прибора

Добавляется JSON-файлом в соответствующую папку — писать код не нужно, если
протокол укладывается в существующую схему (`init_commands`,
`setup_commands`, `output_on`/`output_off`, `measure_command` и т.д. по
образцу). Главное — правильно подобрать `keywords`, встречающиеся в ответе
на `*IDN?`.

## Структура проекта

```
IDM-IVTrace/
├── app.py                # точка входа (используется в сборке exe)
├── run.py                # диспетчер CLI/GUI + предполётная проверка
├── gui.py                # графический интерфейс (Tkinter)
├── cli.py                # argparse + интерактивный ввод + валидация
├── orchestrate.py        # оркестрация сессии измерения (общая для CLI и GUI)
├── measurement.py        # цикл измерения (forward/reverse, кооперативный стоп)
├── instruments.py        # классы приборов + автообнаружение по *IDN?
├── relay.py              # управление платой реле
├── analysis.py           # расчёт погрешности и построение графика
├── config.py             # чтение/запись параметров последнего запуска
├── visa_backend.py       # проверка и создание NI-VISA-бэкенда
├── selftest.py           # предполётные самотесты (гейт перед measure)
├── apppaths.py           # разрешение путей (исходники / собранный exe)
├── instruments/          # JSON-конфиги приборов
├── tests/                # виртуальный тест-набор (pytest)
├── ivtrace.spec          # спецификация сборки PyInstaller (onedir)
├── build_windows.ps1     # скрипт сборки exe
├── requirements.txt      # зависимости рантайма
└── requirements-dev.txt  # + pyinstaller для сборки
```

Данные (`data\`) с CSV/PNG и `ivtrace_config.json` создаются рядом с
программой.

## Разработка и тесты

```bash
conda activate IVTrace
pip install -r requirements-dev.txt
pytest -q            # весь тест-набор
```

Тесты не требуют реального железа — приборы и serial-порт заменены
заглушками (`tests/conftest.py`). Тот же набор гоняется как предполётный
гейт (`selftest.py`) перед каждым измерением, поэтому держите его зелёным.

## Известные ограничения

- Датчики поддерживаются только с **токовым выходом** (измерение всегда
  через `SENS:CURR:DC`). Выход по напряжению — задел на будущее.
- `VoltageSource` (GPP-74323) не проверялся на реальном железе — команды из
  документации.
- Самотесты виртуальные: они ловят поломки логики кода, но не гарантируют
  исправность самих приборов и проводки.
- Для USB-TMC обязательна NI-VISA (см. соответствующий раздел).
